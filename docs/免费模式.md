# NetGuard 免费模式（无驱动 / 无证书）

> 目标：不买 EV 证书、不装内核驱动，也能做到
> **“默认拒绝出网，只放行指定程序 → 指定地址:端口”**。
>
> 适用：Win7 SP1 / Win10 / Win11 的**标准用户终端**（员工不是本地管理员）。
> 不适用：需要“连接瞬间哈希校验”或“防本地管理员”的场景——那仍然要驱动 + EV 签名。

---

## 一、组成

| 层 | 机制 | 作用 |
|---|---|---|
| 出网白名单 | **Windows 防火墙**出站默认阻止 + 按“程序 × 远程地址 × 远程端口 × 协议”放行 | 内核级拦截，开机即生效，服务崩溃也不失效 |
| 收紧系统规则 | 关闭 Windows 自带出站放行规则（212 条左右，按机器不同） | 避免 Windows Update/Store/传递优化等自带规则“漏网” |
| 程序防替换 | 安装脚本收紧程序目录 ACL（SYSTEM/Administrators 完全控制，Users 只读） | 标准用户不能改写/替换白名单 exe |
| 替换检测 | NetGuard 用户态 WFP 策略 + 5 秒快检/30 秒全量 SHA-256 | 发现文件被替换后撤销该程序白名单 |
| 可选 | AppLocker 精确路径规则（`-UseAppLocker`） | 阻止从其他路径启动未批准程序；**实验性**，见第五节 |

> 免费模式不依赖 `ngdrv.sys`，也不需要任何代码签名证书。

---

## 二、使用

```powershell
# 安装服务 + 免费模式（管理员）
powershell -ExecutionPolicy Bypass -File install-netguard.ps1 -FreeMode

# 只做防火墙，不碰 AppLocker（默认）
# 需要 AppLocker 实验特性时：
powershell -ExecutionPolicy Bypass -File install-netguard.ps1 -FreeMode -FreeModeAppLocker

# 保留 Windows 自带出站放行规则（不推荐，会有漏网）
powershell -ExecutionPolicy Bypass -File install-netguard.ps1 -FreeMode -FreeModeKeepBuiltin

# 查看/手工启停
powershell -ExecutionPolicy Bypass -File free-mode.ps1 -Action Status
powershell -ExecutionPolicy Bypass -File free-mode.ps1 -Action Enable
powershell -ExecutionPolicy Bypass -File free-mode.ps1 -Action Disable
```

`install-netguard.ps1 -FreeMode` 会在服务启动后调用 `free-mode.ps1 -Action Enable`；
任何一步失败会自动执行 `Disable` 回滚，避免机器停在“默认阻止但规则不全”的状态。

> **修改策略后必须重新生成防火墙规则**：管理界面保存并 `ctl apply` 只更新用户态 WFP，
> 不会自动改 Windows 防火墙。请在改完后重新执行一次
> `powershell -File free-mode.ps1 -Action Enable`（幂等：会先还原再按新策略重建）。

`uninstall-netguard.ps1` 会在**最后**关闭免费模式：
先恢复默认出站动作、重新启用被关闭的系统规则、删除 NetGuard 规则，再还原 AppLocker。
顺序很关键：`ctl rollback` / `purge` 还需要运行 `C:\NetGuard\NetGuard.exe`，不能提前把程序锁死。

## 三、策略如何映射

以 `policy.ini` 为例：

```ini
[general]
DefaultDeny=1
AllowDhcp=1
AllowLoopback=1
AllowDnsServer=            ; 留空=禁止 DNS
StrictHash=1

[ep.1]
Name=医保前置
Cidr=10.10.10.10/32
Ports=8000-8005
Proto=TCP

[proc.1]
Path=C:\Program Files\YB\YbClient.exe
Sha256=A1B2...
Endpoint=医保前置
```

免费模式生成：

| 策略 | 防火墙规则 |
|---|---|
| `DefaultDeny=1` | 三个配置文件（Domain/Private/Public）`DefaultOutboundAction=Block` |
| `ep.1 + proc.1` | 出站允许：程序 `YbClient.exe` → `10.10.10.10/32`，TCP 8000-8005 |
| `AllowDhcp=1` | UDP 68→67，绑定 `Dhcp` 服务 |
| `AllowDnsServer` | UDP 53 到指定 DNS（任意程序，和用户态策略一致） |
| `LanAllow` + `AllowLanAnyProcess=1` | 任意程序到该网段（TCP/UDP 全端口） |
| `AllowLoopback=1` | Windows 防火墙默认不拦回环，无需额外规则 |

`Proto=ANY` 会拆成 TCP + UDP 两条（ICMP 不在业务白名单内）。
一个程序绑定多个 `Endpoint` 或用逗号分隔多个地址项时，逐个生成。

## 四、实测结果（2026-11-13）

脚本：`lab/free-mode-test.ps1`（安装 → 启用 → 校验 → 卸载恢复）

| 平台 | 结果 | 日志 |
|---|---|---|
| Windows 10 22H2 x64 | **22/22 通过** | `lab/free-mode-test-win10.log` |
| Windows 11 24H2 x64 | **22/22 通过** | `lab/free-mode-test-win11.log` |

覆盖：

- 安装 `-FreeMode` 成功，服务 Running；
- 防火墙规则生成、三配置文件默认出站 Block；
- 系统自带出站规则被关闭（Win10 182 条 / Win11 206 条，按机器不同）；
- 白名单程序 → 指定地址:端口 **放行**（`curl exit=35`）；
- 同一程序 → 其他地址 **拦截**（`exit=7`）；
- 系统 `curl.exe`（未白名单程序）**拦截**（`exit=7`）；
- 复制/改名后的程序 **拦截**（`exit=7`）；
- NetGuard 管理程序仍可运行；
- 卸载后：规则清零、默认出站恢复 Allow、系统规则重新启用、服务删除、网络恢复（`Test-NetConnection=True`）。

## 五、局限与已知问题

1. **对本地管理员无效**：管理员可以改防火墙、停服务、改 ACL。
   免费模式的安全边界是“标准用户”。如果店员是本地管理员，任何用户态方案都不成立，
   需要域控/GPO/MDM，或硬件网关。
2. **没有“连接瞬间哈希”**：文件被替换后，用户态巡检需要约 3 秒发现；
   程序目录 ACL 让标准用户无法替换，但管理员/安装程序可以。
   要彻底消除窗口，仍需 `drv/ngdrv.sys` + EV 签名。
3. **AppLocker 是实验性开关**：在测试的 Win10 22H2 上，本地策略里的
   `FileHashRule` 会导致整个 Exe 集合不编译（表现为“策略已应用但完全不拦”）；
   精确 `FilePathRule` 可以正常拦截，但策略缓存需要强制重建，行为不稳定。
   因此默认**不启用** AppLocker，只用防火墙 + ACL。
4. **会断开系统更新/商店/时间同步**：关闭系统自带出站规则后，
   Windows Update、Microsoft Store、NTP、部分遥测会失败。
   如确需，按同样的“程序 × 地址 × 端口”方式显式放行（或用 `-KeepBuiltinRules`）。
5. **DNS 默认禁止**：和用户态策略一致；业务必须用固定 IP，或显式配置 `AllowDnsServer`。
6. **DHCP 依赖 `Dhcp` 服务**：静态 IP 终端可以关掉 `AllowDhcp`。
   当前只生成 DHCPv4（68→67）；如使用 IPv6，需要额外放行 DHCPv6（546→547）
   和 ICMPv6 邻居发现（133–136），否则关闭系统规则后 IPv6 可能不可用。
7. **RDP / PowerShell Direct 不受影响**：只改出站，入站规则和 VMBus 不变。
8. **回滚依赖状态文件**：`%ProgramData%\NetGuard\freemode-state.json` 记录原默认动作和被关闭的系统规则；
   丢失后仍能删 NetGuard 规则并把默认出站恢复 Allow，但系统自带规则需要手工确认。

## 六、与付费驱动方案对比

| 能力 | 免费模式 | 驱动 + EV |
|---|---|---|
| 默认拒绝出网 | ✅ | ✅ |
| 程序 × 地址 × 端口 | ✅（路径绑定） | ✅（路径 + 连接时哈希） |
| 阻止复制/改名程序 | ✅ | ✅ |
| 阻止原地替换（标准用户） | ✅（ACL） | ✅（哈希门禁） |
| 阻止原地替换（管理员） | ❌ | 部分（驱动仍可被管理员停止） |
| 连接瞬间哈希 | ❌（约 3 秒巡检） | ✅ |
| 成本 | **0 元** | EV 证书 ¥2–4k/年 + 签名/测试 |
| 部署 | 内置防火墙，无驱动 | 需签名驱动、Partner Center |

## 七、排障

```powershell
# 看当前规则
Get-NetFirewallRule -Group 'NetGuard-FreeMode' | Format-Table DisplayName,Enabled,Action

# 看默认出站动作
Get-NetFirewallProfile -Profile Domain,Private,Public |
  Select-Object Name,DefaultOutboundAction

# 看状态/日志
powershell -File free-mode.ps1 -Action Status
Get-Content "$env:ProgramData\NetGuard\freemode.log" -Tail 50

# 紧急恢复联网（不删服务）
powershell -File free-mode.ps1 -Action Disable
```

常见现象：

| 现象 | 处理 |
|---|---|
| 业务程序能连、其他程序全断 | 正常；检查规则是否覆盖了正确的程序路径/地址/端口 |
| 业务程序也被断 | 确认 `Program` 路径与实际启动路径一致（含 `SysWOW64` 重定向） |
| 域名访问失败 | 默认禁止 DNS；改用固定 IP，或配置 `AllowDnsServer` |
| 系统更新失败 | 预期；需要时显式放行更新程序，或 `-KeepBuiltinRules` |
| 卸载后仍断网 | `free-mode.ps1 -Action Disable`；状态文件丢失时手工把默认出站改回 Allow |
| AppLocker 开启后程序全被拦 | 先 `-Action Disable`；该特性在部分 Win10 本地策略上不稳定，建议保持关闭 |

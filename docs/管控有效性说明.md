## 一、管控目标（可验收的硬指标）

| 编号 | 要求 | 验收判据 |
|---|---|---|
| R1 | 默认**拒绝一切出网**流量（IPv4 与 IPv6 全协议） | 白名单外的目标一律超时/拒绝；浏览器、微信、迅雷等全部不可用 |
| R2 | 仅放行**指定程序 → 指定地址:端口**的组合 | 同一地址换一个程序访问照样被拦（证明不是"只放 IP"） |
| R3 | 策略不可被普通员工解除 | 员工为**标准用户**，改不动服务、策略文件与过滤器 |
| R4 | 过滤器被删会自动恢复；服务崩溃会被拉起 | 看门狗每 30 秒按 `filters.txt` 逐条核验实际过滤器，缺失即重建并留审计；服务失败动作 5s/15s/60s 重启 |
| R5 | 木马不能借用医保通道 | 白名单与**业务程序的 SHA-256 哈希**绑定；程序被替换即撤销该条白名单 |
| R6 | 可审计、可出具检查证据 | `audit.log` / `ng.log` / `filters.txt` + `NetGuard test` 自检输出 |

## 二、技术实现（分四层）

```
第 0 层  管理措施：员工账户=标准用户 / BIOS 密码 / 禁用 U 盘启动 / 机箱锁
第 1 层  常驻服务：NetGuard 服务（LocalSystem，开机自启，失败自动重启）
第 2 层  网络强制：Windows Filtering Platform（WFP）ALE_AUTH_CONNECT 层
         ├─ 默认拒绝：IPv4 + IPv6 各一条 BLOCK（最高优先级被显式 permit 覆盖）
         ├─ 基础放行：回环 127.0.0.0/8 + ::1、DHCP（UDP 68→67）
         └─ 业务白名单：程序(A) × 目的地址(CIDR) × 端口 × 协议 四元绑定
第 3 层  自保护与审计：服务 DACL / 策略目录 ACL / 每机随机策略密钥 / 过滤器 ID 清单 / 哈希校验 / 审计日志
```

关键设计说明（非技术人员可略读）：

1. **为什么用 WFP 而不是"关掉网卡"或"改 hosts"**：关网卡会连医保也断；改 hosts 只能挡域名，挡不住 IP 直连。WFP 是 Windows 内核里的过滤引擎（与系统防火墙同一套），可在"连接发起瞬间"按程序身份与目标地址精确裁决。
2. **为什么业务白名单要绑定程序**：如果只放行"医保前置 IP:8000"，那么任何木马都能连这个地址去打医保服务器。绑定程序后，只有被批准的 exe 能用这条通道（R5）。
3. **为什么绑定哈希**：员工若把业务 exe 换成自己的程序（同名），路径没变但内容变了；哈希校验能识别并立即撤销该条白名单。
4. **为什么"过滤器是会话级"反而是优点**：过滤器由服务进程持有。服务一旦被停/崩溃，过滤器随之消失，机器恢复联网 —— **不会把门店留在"永久断网"的故障状态**；这也是"失败即安全"的含义。开机时服务先于用户登录即下发策略，因此不存在"开机到策略生效"的空窗。

## 三、验收测试方法（可在任意门店终端复现）

### 场景 A：默认拒绝是否生效（R1）

```bat
:: 1) 未下发策略时的基线（应能连出去）
C:\NetGuard\NetGuard.exe selftest

:: 2) 端到端测试：基线 → 应用 → 再测 → 回滚 → 再测（约 15 秒）
C:\NetGuard\NetGuard.exe test
```

判读：`test` 最后打印

```
==== 结果 ====
  基线: 能连出去 (OK)
  应用后: 全部拦截 (PASS)
  回滚后: 恢复连接 (OK)
```

退出码 `0` 为通过。

### 场景 B：服务是否在"无人登录"时就生效（R4 的前半）

```powershell
# 重启终端后，不登录任何账户，直接以管理员查看
C:\NetGuard\NetGuard.exe ctl status
```

期望：`filters >= 4`、`default_deny=1`；`C:\ProgramData\NetGuard\audit.log` 中出现
`ACTION service-start filters=N`。

### 场景 C：程序被替换后是否自动撤销白名单（R5）

1. 管理界面中把"业务程序"选为 `C:\NetGuard\biz.exe`（自动生成 SHA-256），保存并应用；
2. 管理员用**另一个程序**覆盖 `C:\NetGuard\biz.exe`（模拟被替换）；
3. 等待 ≤ 40 秒，然后：
   ```powershell
   C:\NetGuard\NetGuard.exe ctl status
   ```
   期望：过滤器数量**减少 1**（业务白名单被撤），
   `audit.log` 出现 `ALERT hash-changed …` 与 `ACTION revoked-mismatched-programs and re-sign policy`，
   `policy.ini` 中该程序的 `Enable=0`。

## 四、实测证据（本机环境，可复现）

测试环境：宿主 Windows 11 + Hyper-V；客户机分别为 Windows 7 SP1 x64 与 Windows 10 22H2 x64（干净安装）。

> 注：以下实测数据采集于“5 条过滤器 + 固定密钥”版本；后续新增 IPv6 回环 `::1` 后典型过滤器数为 6 条，
> 并将策略密钥改为每机随机（`HKLM\SOFTWARE\NetGuard\PolicyKey`）。

### 4.1 Windows 10 22H2

| 步骤 | 输出 |
|---|---|
| 基线自检 | `[LEAK] 8.8.8.8:53 CONNECTED (203ms)`、`[LEAK] 114.114.114.114:53 CONNECTED (47ms)` |
| `apply` | `[ok] 策略已生效，过滤器 5 条` |
| 应用后自检 | 4/4 目标 `[BLOCK] … err=10060 (0ms)`（0 毫秒即拒绝 = 本地主动丢弃，而非网络不通） |
| `rollback` | `[ok] 已撤销 NetGuard 全部过滤器（恢复联网）` |
| 回滚后自检 | 恢复 `CONNECTED` |
| 端到端结论 | `EXITCODE=0` |

### 4.2 Windows 7 SP1 x64

| 步骤 | 输出 |
|---|---|
| 基线自检 | `[LEAK] 172.30.18.120:3389 CONNECTED (31ms)`（局域网）<br>`[LEAK] 8.8.8.8:53 CONNECTED (203ms)`（外网）<br>`[LEAK] 114.114.114.114:53 CONNECTED (47ms)` |
| `apply` | `[ok] 策略已生效，过滤器 5 条` |
| 应用后自检 | **5/5 目标全部 `[BLOCK]`，均为 0ms** |
| `rollback` | `[ok]`（删除 5 条） |
| 回滚后自检 | 3 个目标恢复 `CONNECTED` |
| 端到端结论 | `EXITCODE=0` |


### 4.5 抗篡改配置（安装后实测值）

```
服务 SDDL : D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)
            → 仅 SYSTEM 与 Administrators 可启停/改配置；标准用户无权限
失败动作   : restart/5s、restart/15s、restart/60s（reset=86400s）—— 崩溃自动拉起
数据目录   : C:\ProgramData\NetGuard
            SYSTEM: 完全控制    Administrators: 完全控制    Users: 只读
admin.dat  : 仅 SYSTEM / Administrators 可读写（普通用户无法读取口令盐/哈希）
策略文件   : 带 HMAC-SHA256 签名；被手工修改后 apply 会拒绝（签名校验失败）
策略密钥   : 首次安装或密钥缺失时随机生成，存 HKLM\SOFTWARE\NetGuard\PolicyKey；
             键 DACL 仅 SYSTEM/Administrators，普通用户无法预置或读取
策略签名   : 密钥缺失或签名无效时，服务与命令行一律拒绝下发（fail-closed），
             并在 audit.log 记录 ALERT policy-signature-missing/invalid；
             旧策略可经管理员确认后执行 NetGuard.exe sign 重新签名
```

## 六、边界与配套管理措施（必须同时落实，否则本机能被绕过）

本组件运行在操作系统之内，以下情形**软件无法防御**，需管理制度配合：

| 风险 | 配套措施 |
|---|---|
| 员工拿到**本机管理员**口令后停用服务/卸载 | 管理员口令由店长/总部掌握；本组件已把服务 DACL 收紧为"仅管理员"，并要求管理界面二次口令 |
| 用 PE/U 盘启动、拆盘读取 | BIOS 设置开机密码 + 禁用 USB 启动 + 机箱锁 |
| 员工私自更换业务程序 | 哈希锁定会自动撤销白名单并留审计记录（4.4） |
| 医保业务本身的漏洞 | 本组件只约束"本机出网"，医保服务器侧仍需其自身防护 |
| Windows 7 已停止官方支持 | 建议逐步替换为 Windows 10 LTSC；更换前本组件可继续使用 |

## 十、结论

在 Windows 7 SP1 x64 与 Windows 10 22H2 x64 上，本组件均实测做到：

1. **默认拒绝一切出网流量**，仅放行"已批准程序 → 已批准地址:端口"（实测 5/5 目标 0ms 拦截）；
2. **策略可逆**，回滚后网络立即恢复，不会把终端留在断网状态；
3. **开机即可生效**（SYSTEM 服务，无需用户登录）；
4. **可抵抗普通员工**（标准用户 + 服务 DACL + 策略目录只读 + 每机随机密钥 + 看门狗）；
5. **可识别业务程序被替换**（SHA-256 锁定，30 秒内撤销白名单并留审计）；
6. **具备检查所需的审计留痕与现场演示手段**。

需要配套落实的仅有第 0 层管理措施（生物/物理层面）：管理员口令保管、BIOS 密码、禁用 U 盘启动。

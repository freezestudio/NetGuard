## 0. 环境与最终选择

宿主：Lenovo 82JQ / Ryzen 7 5800H（8C16T）/ 15.9 GB RAM / C: 476 GB（原可用 331 GB）/ Windows 11 专业版 build 26300。

关键前提（决定了技术选型）：

- **VBS 内存完整性（HVCI）已在运行**，且 **WSL2(Ubuntu-26.04) 在用** → 宿主 hypervisor 已存在。
- 因此 VMware / VirtualBox 只能跑在 WHP 兼容层，性能打折；且 AMD 宿主在 Hyper-V 模式下**没有嵌套虚拟化**。
- VMware Workstation 已从 winget 下架，需 Broadcom 账号手动下载。

**结论：用 Hyper-V（Windows 内置）。** 原生零损耗，且是微软官方推荐的驱动开发测试目标。

## 1. 启用 Hyper-V（需一次提权 + 重启）

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -NoRestart
```
验证：`vmms` 服务自动启动、`hvhost` 运行、`Default Switch`（内部 NAT）存在。

权限提示：普通管理员登录会话里 `Get-VM` 仍会被拒（UAC 过滤令牌）。
解决：把账户加入 **Hyper-V Administrators** 组，**重新登录后生效**；
```powershell
Add-LocalGroupMember -Group 'Hyper-V Administrators' -Member "$env:COMPUTERNAME\$env:USERNAME"
```

## 3. 虚拟机规格与创建

```powershell
$w10='Win10-Pro-22H2'
New-VM -Name $w10 -Generation 2 -MemoryStartupBytes 6GB `
       -NewVHDPath "infra\vms\$w10\disk.vhdx" -NewVHDSizeBytes 80GB -SwitchName 'Default Switch'
Set-VMProcessor $w10 -Count 4
Set-VMMemory    $w10 -DynamicMemoryEnabled $true -MinimumBytes 3GB -StartupBytes 6GB -MaximumBytes 8GB
Set-VMFirmware  $w10 -EnableSecureBoot Off          # 必须关！否则 testsigning 失效
Add-VMDvdDrive  $w10
Set-VMComPort   $w10 -Path '\\.\pipe\win10dbg' -Number 1

$w7='Win7-Pro-x64'
New-VM -Name $w7 -Generation 1 -MemoryStartupBytes 3GB `
       -NewVHDPath "infra\vms\$w7\disk.vhdx" -NewVHDSizeBytes 60GB
Set-VMProcessor      $w7 -Count 2
Set-VMMemory         $w7 -DynamicMemoryEnabled $false -StartupBytes 3GB   # Win7 不用动态内存
Add-VMNetworkAdapter $w7 -SwitchName 'Default Switch' -IsLegacy $true     # Win7 只有 Legacy 网卡有驱动
Add-VMDvdDrive       $w7
Set-VMBios           $w7 -StartupOrder @('CD','IDE','LegacyNetworkAdapter','Floppy')
Set-VMComPort        $w7 -Path '\\.\pipe\win7dbg' -Number 1
```

## 4. 安装系统：为什么最后走"离线部署"

### 走过的弯路
1. **交互式 Setup（挂 ISO + 应答文件放第二块盘）**：Win10 起来后停在等待界面，**磁盘 4 MB 一直不增长** → 应答文件没被扫描到，安装永远不开始。Win7 同样不可靠。
2. **官方 MCT 生成 ISO**：返回 `0xC190010D`。

### 最终方案：离线应用映像（不用 Setup 交互）

流程（`offline-install.ps1`）：
1. 建 80 GB 动态 VHDX，GPT 分区：ESP 300 MB(FAT32) + MSR 16 MB + 主分区(NTFS)
2. `Mount-DiskImage` 挂 ISO → `Get-WindowsImage` 找 **`Windows 10 专业版`** 的索引（=4）
3. `Expand-WindowsImage -Index 4 -ApplyPath W:\`（实测 1.3 分钟）
4. `bcdboot` 建引导（见 §5 的坑）
5. 把 **仅含 oobeSystem 的 `unattend.xml`** 放到 `W:\Windows\Panther\unattend.xml`
6. 卸盘、设硬盘为第一启动设备、开机 → OOBE 自动跑完、自动登录、`FirstLogonCommands` 执行配置

`unattend.xml` 的关键内容（`infra\vms\answer\Win10\unattend-oobe.xml` 的原型）：

- `Microsoft-Windows-International-Core`：`zh-CN` / `0804:00000804`
- `OOBE`：`HideEULAPage/HideLocalAccountScreen/HideOnlineAccountScreens`
- `UserAccounts`：本地管理员 `freeze`，密码明文 `1`
- `AutoLogon`：`freeze`，`LogonCount=2`
- `FirstLogonCommands`（8 条，**在管理员上下文执行**）：
  1. `bcdedit /set testsigning on`
  2. `bcdedit /debug on`
  3. `bcdedit /dbgsettings serial debugport:1 baudrate:115200`
  4. `powercfg -h off`
  5. 注册表开 RDP（`fDenyTSConnections=0`）
  6. 防火墙放行 3389
  7. 关首次登录动画
  8. `echo installed-fine > C:\OOBE-DONE.txt`（验收标记）

> Win7 当年用的是"ISO + 应答文件"路线装成的（`prepare-install.ps1`），结果发现它的 `FirstLogonCommands` 里 `testsigning`/`debug` **两条没生效**（只有 `dbgsettings` 生效），后来用离线 `bcdedit /store` 补上了。

## 5. 踩坑清单（都是实测结论）

| # | 症状 | 原因 | 解法 |
|---|---|---|---|
| 1 | `param($VM)` 脚本一跑就报 "value ... is not a valid value for the VM variable" | PowerShell 变量名**不区分大小写**，`$vm = Get-VM` 撞上带 `ValidateSet` 的 `$VM` | 参数改名（如 `$Target`） |
| 2 | `bcdboot` 返回 193、`0xc1`，提示找不到 `boot\EFI_EX\bootmgfw_EX.efi` | 宿主 Win11 的 bcdboot 检测到**本机开了 Secure Boot**，强制使用 2023 PCA 签名的 Ex 版本，而旧镜像里没有 | ① 优先调用**镜像自带的 bcdboot**（`W:\Windows\System32\bcdboot.exe`）；② 22H2 镜像自带 Ex 文件，宿主 bcdboot 直接可用 |
| 3 | 固件报 **`0xc000000e`**（Your PC needs to be repaired） | 用"导出宿主 BCD 当模板"再 `bcdedit /set device partition=W:`，写入的是**宿主相对设备路径**，客户机解析不了 | 不要手工造 BCD store，用 bcdboot 生成 |
| 4 | `bcdedit /createstore` 报"文件已存在" | 该命令**不接受自定义路径**，只能在系统 store 位置建 | 同上 |
| 5 | `Remove-VMHardDiskDrive -ControllerNumber` 报 ControllerType 转换错误 | 参数集不匹配 | 用 `Remove-VMHardDiskDrive -VMHardDiskDrive $obj` |
| 6 | `Stop-VM -Force` 关不掉 | `-Force` 走正常关机流程 | 要断电用 `Stop-VM -TurnOff` |
| 7 | 计划任务里的 .ps1 报奇怪的语法错误 | SYSTEM 任务用 **PowerShell 5.1**，按 GBK 解析无 BOM 的 UTF-8 中文 | 给 .ps1 加 **UTF-8 BOM**（`New-Object Text.UTF8Encoding($true)`） |
| 8 | 非提权会话 `Get-VM` 被拒 | UAC 过滤令牌 + 不在 Hyper-V Administrators 组 | 提权脚本，或加组后**重新登录** |
| 9 | 看不到虚拟机画面 | 无 GUI 工具 | WMI `Msvm_VirtualSystemManagementService.GetVirtualSystemThumbnailImage` 抓缩略图（**返回裸 ARGB**，需 `Bitmap.LockBits + Marshal.Copy` 转 PNG） |
| 10 | Win7 ISO 从 CD 启动后一直等按键 | 交互式 Setup 需要人工点击 | 改离线部署（§4） |
| 11 | `winget` 装不到 VMware Workstation | Broadcom 已下架 winget 分发 | 只能用 Hyper-V（或手工注册账号下载） |

## 6. 两个很有用的"接口逆向"记录

### 6.1 iTellyou（MSDN,我告诉你）API

老站 `msdn.itellyou.cn` 是索引站，只提供 **eD2K 链接 + SHA1**（没有 HTTP 直链）。ASP.NET Core + antiforgery：

- CSRF token 在 **`<body data-token=...>`** 里
- 必须**同时**带上 `/` 响应下发的 `.AspNetCore.Antiforgery.*` cookie，否则一律 400

```text
GET  https://msdn.itellyou.cn/            → 取 data-token + set-cookie
POST /Index/Search   {keyword, filter}    → result.list[].product[].url 即 eD2K 链接
```
（新站 `next.itellyou.cn` 的 `/Original/Index` 会 302 到注册页，需登录。）

### 6.2 迅雷静默投任务（32 位 COM）

x64 PowerShell 创建 `ThunderAgent.Agent.1` 会报 `REGDB_E_CLASSNOTREG`（注册成 32 位），
必须用 `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`，且 **AddTask 是 8 个参数**：

```powershell
$a = New-Object -ComObject ThunderAgent.Agent.1
$a.AddTask.Invoke([object[]]@($url, $fileName, 'C:\迅雷下载', '', '', 1, 0, 5))
$a.CommitTasks()
```
另有协议处理器可直接投递：`Start-Process 'ed2k://|file|xxx.iso|<size>|<hash>|/'`。

## 7. Win7 离线补丁

补丁源：Microsoft Update Catalog。搜索页的行 id 形如 `<guid>_R1/<guid>_R2...`（**行号后缀**），
下载直链通过 `POST /DownloadDialog.aspx` 加 `updateIDs=[{"size":0,"updateID":"<guid>","uidInfo":"<guid>"}]` 获取。

| KB | 作用 | 结果 |
|---|---|---|
| KB3020369 | 2015-04 服务栈更新（便利汇总的前置） | exit=0 |
| KB4490628 | 2019-03 服务栈更新（SHA-2 的前置） | exit=0 |
| KB4474419 | **SHA-2 代码签名支持**（必需，否则现代证书/安装包全失败） | exit=3010 |
| KB3125574 | SP1 便利汇总（476.9 MB） | exit=3010 |
| KB3140245 | **TLS 1.1/1.2 支持**（配合注册表 `DefaultSecureProtocols=0xA00`） | exit=3010 |

`3010` = 成功但需重启。

**注入方式（全自动，无需远程执行通道）**：Win7 没有集成服务、也没有 PowerShell Direct，所以
1. 关机 → 挂载 VHDX → 把 MSU 拷到客户机 `C:\patches`
2. 写 `C:\patches\apply.cmd`（顺序安装 + TLS 注册表 + 恢复 UAC + 重启）
3. **离线改注册表**（挂 `SYSTEM`… 实际是 `SOFTWARE` hive）：
   - `Policies\System\EnableLUA = 0`（临时关 UAC，否则 RunOnce 里的 `wusa` 会被拦）
   - `Winlogon`：`AutoAdminLogon=1` / `DefaultUserName=freeze` / `DefaultPassword=1`
   - `RunOnce`：`Win7Patches = C:\patches\apply.cmd`
4. 开机 → 自动登录 → RunOnce 执行 → 装完自己恢复 UAC 并重启

下载小技巧：官方 CDN `catalog.s.download.windowsupdate.com` 在本地单连接只有 1–20 KB/s，
**必须用多连接**（`aria2c -x16 -s16`）才能跑到几百 KB/s。所有 MSU 都用 `Get-AuthenticodeSignature` 验过微软签名。

## 9. Win11-Test 虚拟机（2026-11-13 追加）

### 9.1 为什么不用 Windows Sandbox

先评估过 Windows Sandbox，结论是不适合：

- 宿主 `Containers-DisposableClientVM = Disabled`，开箱功能需要重启；
- Sandbox 不能安装/加载内核驱动（NetGuard 的核心验证目标）；
- 宿主开着 VBS/HVCI + Secure Boot，Sandbox 内也不能关；
- 每次启动都是全新环境，无法保留 testsigning 配置和快照。

因此改为建一台普通 Gen2 虚拟机 `Win11-Test`，可自由关 Secure Boot、开 testsigning、做快照。

### 9.2 镜像获取与无人值守

```text
镜像：Win11 Enterprise Evaluation 24H2（10.0.26100）
链接：https://go.microsoft.com/fwlink/?linkid=2289031
大小：5,387,960,320 字节（SHA-256 755a90d4…3622ae）
```

- 官方 ISO 的 `efi\microsoft\boot\efisys.bin` 会提示 “Press any key to boot from CD/DVD”，
  而无人值守安装没人按键就会跳过光盘。
- 解决：装 ADK Deployment Tools（`oscdimg.exe`），把 ISO 内容复制出来，
  根目录放 `autounattend.xml`，再用
  `-bootdata:2#p0,e,b"boot\etfsboot.com"#pEF,e,b"efi\microsoft\boot\efisys_noprompt.bin"`
  重新打包成 `Win11-EnterpriseEval-24H2-unattend.iso`。
- `autounattend.xml` 负责：语言 en-US、跳过 OOBE/联网账户、
  创建本地管理员 `freeze`/`1`、自动登录（`LogonCount=999`）、计算机名 `WIN11-TEST`、时区。
- 实际安装时 **磁盘分区页仍需手工点一次**（`DiskConfiguration` 未自动生效），
  其余账户/自动登录/OOBE 均按应答文件生效。

### 9.3 硬件与安全配置

```text
Gen 2 / 4 vCPU / 6 GB 固定内存 / 80 GB 动态 VHDX / vTPM / Default Switch
Secure Boot：先 On 装完，再 Off（加载测试签名驱动）
testsigning：on；nointegritychecks：on
Device Guard / VBS：VirtualizationBasedSecurityStatus = 0（无 HVCI）
```

坑：

- `Set-VM -TpmEnabled` 参数不存在 → 用 `Enable-VMTPM`（先 `Set-VMKeyProtector -NewLocalKeyProtector`）。
- **启用 vTPM 后 Secure Boot 模板锁死**，只能开关 Secure Boot，不能改模板；
  且 Secure Boot 只能在 VM 关机时切换。
- 评估版约 90 天到期。

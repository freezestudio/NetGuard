## 一、自动登录（三台都已配置）

### 1. 账号

| 虚拟机 | 用户名 | 密码 | 权限 |
|---|---|---|---|
| Win7-Pro-x64 | `freeze` | `1` | 本地管理员 |
| Win10-Pro-22H2 | `freeze` | `1` | 本地管理员 |
| Win11-Test | `freeze` | `1` | 本地管理员 |

### 2. 注册表值

客户机内路径：

```text
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon
```

| 值 | 数据 | 说明 |
|---|---|---|
| `AutoAdminLogon` | `1` | 开启自动登录 |
| `DefaultUserName` | `freeze` | 登录账号 |
| `DefaultPassword` | `1` | 登录密码（明文，仅实验环境） |
| `DefaultDomainName` | 计算机名 | Win7=`FREEZE-PC`，Win10=`DESKTOP-D7QNE9M`，Win11=`WIN11-TEST` |
| `ForceAutoLogon` | `1` | 注销后仍自动登录 |

> Win11 的自动登录是安装阶段由 `autounattend.xml` 写入的（`LogonCount=999`），
> 没有经过 `configure-vms.ps1`；如果以后改密码，仍要同步改 `DefaultPassword`。

另外：

```text
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System
  DisableCAD = 1        （不要求 Ctrl+Alt+Del）
  EnableLUA  = 0        （Win7 已关闭 UAC；Win10 未改）
```

### 3. 已验证

- Win7：开机后直接进入桌面（已截图 `infra\vms\launch\win7-autologin.png`），没有登录界面。
- Win10：PowerShell Direct 读取 `AutoAdminLogon=1`，计算机名 `DESKTOP-D7QNE9M`。
- Win11：PowerShell Direct 登录身份为 `win11-test\freeze`，OOBE 已跳过，直接进桌面。
- 如果以后修改了 `freeze` 的密码，必须同步更新 `DefaultPassword`，否则自动登录会失败。

## 二、剪贴板

### 1. Win10（推荐增强会话）

宿主机已开启：

```powershell
Set-VMHost -EnableEnhancedSessionMode $true
```

Win10 支持 Hyper-V 增强会话，VMConnect 增强会话默认支持剪贴板。

两种入口：

| 入口 | 方式 | 剪贴板 |
|---|---|---|
| `infra\vms\启动Win10.cmd` | VMConnect（增强会话） | 支持 |
| `infra\vms\连接Win10-剪贴板.cmd` | RDP（`redirectclipboard:i:1`） | 支持 |

### 2. Win7（必须用 RDP）

Win7 **不支持** Hyper-V 增强会话，因此 `vmconnect` 的剪贴板不可用；使用 RDP：

| 入口 | 方式 | 剪贴板 |
|---|---|---|
| `infra\vms\连接Win7-剪贴板.cmd` | RDP + `redirectclipboard:i:1` | 支持 |
| `infra\vms\启动Win7.cmd` | VMConnect 基本会话 | 不支持（仅控制台） |

首次连接注意：

1. 如果出现“远程桌面连接安全警告 / 未知发布者”，勾选 **剪贴板**，再点 **连接**。
2. 如果出现“无法验证远程计算机的身份”，勾选 **不再询问**，点 **是**。
3. 之后 `cmdkey` 已保存 `TERMSRV/172.20.192.50`、`TERMSRV/172.20.192.51`，
   正常不需要再输入密码。

### 3. Win11（VMConnect 增强会话）

Win11 支持 Hyper-V 增强会话，直接 `启动Win11.cmd` 即可；需要客户机内允许增强会话。
当前 Win11 主要用于驱动测试，没有单独的 RDP 剪贴板入口。

| 入口 | 方式 | 剪贴板 |
|---|---|---|
| `infra\vms\启动Win11.cmd` | VMConnect（增强会话） | 支持（需客户机允许增强会话） |

### 4. RDP 参数（启动器自动生成）

`infra\vms\launch\connect-rdp.ps1` 会生成：

```ini
full address:s:172.20.192.50
username:s:freeze
prompt for credentials:i:0
authentication level:i:0
enablecredsspsupport:i:1
redirectclipboard:i:1
```

启动器还会：

- 关闭已有的 `vmconnect.exe` / `mstsc.exe`；
- 把其它所有 VM `Stop-VM -Save`；
- 只启动目标 VM；
- 等待 3389 端口；
- 用 `cmdkey` 保存凭据；
- 打开**一个** `mstsc` 窗口。

### 5. 已验证/已知情况

- `Test-NetConnection 172.20.192.50 -Port 3389` → **True**。
- `Test-NetConnection 172.20.192.51 -Port 3389` → **True**。
- 实际运行 `连接Win7-剪贴板.cmd` 和 `连接Win10-剪贴板.cmd` 均成功：
  - `rdp-Win7 - 172.20.192.50 - 远程桌面连接`
  - `rdp-Win10 - 172.20.192.51 - 远程桌面连接`
- `accept-rdp.ps1` 会自动在安全警告里勾选 **剪贴板** 并点 **连接**，
  不需要手工点（基于 UI Automation，按控件实际位置点击）。
- 由于 Win7 客户机内 Explorer 的任务栏在实验室环境中偶尔处于异常状态，
  自动化“粘贴到记事本”的验证没有稳定跑通；这不影响 RDP 剪贴板重定向配置。
  如果桌面没有任务栏，注销/重启客户机后再连接即可。

## 四、单虚拟机 / 单连接规则

### 1. 行为

`infra\vms\launch\vm-common.ps1` 中的 `Start-OneVm`：

1. 获取全局互斥锁（防止两个启动器同时跑）；
2. 关闭所有 `vmconnect.exe` 和 `mstsc.exe`；
3. 把其它所有 VM 保存（`Stop-VM -Save`），失败才 `-TurnOff`；
4. 启动目标 VM；
5. 只打开一个连接：
   - 控制台入口 → 一个 `vmconnect`；
   - 剪贴板入口 → 一个 `mstsc`。

### 2. 入口

| 场景 | 双击 |
|---|---|
| Win7 控制台 | `infra\vms\启动Win7.cmd` |
| Win10 控制台 | `infra\vms\启动Win10.cmd` |
| Win11 控制台 | `infra\vms\启动Win11.cmd` |
| Win7 剪贴板 | `infra\vms\连接Win7-剪贴板.cmd` |
| Win10 剪贴板 | `infra\vms\连接Win10-剪贴板.cmd` |

> 不要手工同时 `Start-VM` 多台；内存只有 16 GB。

### 3. 日志

```text
infra\vms\launch\launcher.log
```

会记录：关闭了几个旧窗口、其它 VM 的保存/关机、启动目标、打开了一个连接。

## 五、重新配置

需要管理员权限（会停止所有 VM、挂载 VHD 改注册表、重启验证）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File infra\vms\launch\configure-vms.ps1
```

> 该脚本只覆盖 **Win7 / Win10**；Win11 的自动登录是安装时 `autounattend.xml` 写入的，
> 不在脚本范围内。需要改 Win11 配置时用 PowerShell Direct 直接进入客户机修改。

脚本会：

1. 关闭所有 VM；
2. Win7 离线挂载 VHD：
   - 写自动登录；
   - 开 RDP（`fDenyTSConnections=0`、NLA 关闭、TermService 自动）；
   - 写 RunOnce：放行 3389 防火墙 + 固定 IP；
   - 启动 Win7，等待 3389 可连；
3. Win10 通过 PowerShell Direct：
   - 写自动登录；
   - 开 RDP / 防火墙；
   - 固定 IP `172.20.192.51`；
   - 验证 3389；
4. 主机侧保存 `cmdkey` 凭据。

## 七、排障

| 现象 | 处理 |
|---|---|
| 开机停在登录界面 | 检查 `Winlogon` 的 `AutoAdminLogon` / `DefaultPassword`；密码是否改过 |
| RDP 连不上 | `Test-NetConnection <ip> -Port 3389`；检查客户机防火墙 3389 规则；检查静态 IP |
| RDP 提示“已建立另一个连接” | 客户机控制台还在自动登录/恢复；等 30–60 秒再连 |
| 剪贴板不能粘贴 | 首次连接的安全警告里是否勾选了“剪贴板”；重新运行 `连接*-剪贴板.cmd` |
| 桌面没有任务栏 | Win7 客户机 Explorer 状态问题；注销/重启客户机，或直接用 RDP 入口 |
| 多台 VM 同时运行 | 关闭 Hyper-V 管理器里的多余 VM；启动器只保证从它启动时单 VM |
| Win11 改不了 Secure Boot | 必须先把 VM 关机；启用过 vTPM 后模板锁定，只能开关 Secure Boot，不能换模板 |
| Win11 PS Direct 连不上 | 确认 VM 已启动完成、`vmicvmsession` 服务存在、宿主机是管理员 |
| Win11 加载驱动失败 | 确认 `bcdedit` 里 `testsigning Yes`、Secure Boot Off；测试证书已导入受信任根 |
